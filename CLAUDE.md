# Claude Guidelines

AI directives only (permissions, guardrails, doc references) — project conventions belong in `docs/`.
Rules must be concise. One rule per line when possible.

## General

- Project uses `just` (justfile), not `make` (Makefile)
- File names: lowercase (e.g., `architecture.md`)
- Check existing docs before creating new files
- Write in English, be concise, skip obvious examples
- Favor rigorous, definitive solutions — no shortcuts, no temporary fixes, no lazy workarounds

## Git

- Commit conventions: follow `docs/git-commits.md` strictly
- Issue conventions: follow `docs/git-issues.md` strictly
- Git workflow: follow `docs/git-workflow.md` strictly
- Releases: `CHANGELOG.md` is the source of truth; use `/release` (stops for approval before the develop→main merge and the tag) — never release autonomously
- Never use `git commit` directly, only `/git-commit` command
- Never merge a PR directly (`gh pr merge`, etc.), only `/gh-merge-develop` command
- Never use `gh issue create` directly, only `/gh-issue` command
- Never use `gh pr create` directly, only `/gh-pr-create` command
- Never commit directly on `main` or `develop` — always a feature branch + PR (enforced by `.githooks/pre-commit`)
- Before making changes, check branch — if on `main` or `develop`, propose a branch name and wait
- Unrelated bug found during work: create a GitHub issue, never fix it in the current branch
- No AI references (Co-Authored-By, Generated by, etc.) in commits or code

## Code

- Follow `docs/code.md` strictly
- Architecture reference: `docs/architecture.md`
- Be strict and uncompromising — flag security, performance, and design issues immediately
- Reject shortcuts, quick hacks, and unjustified technical debt

## Testing

- Never modify existing tests without explicit approval
- If a test fails after code changes, report it instead of fixing it silently
- Adding new tests is always allowed
- Bug fixes start with a failing regression test that reproduces the bug (reference the issue number in the test); see `docs/code.md` Testing
